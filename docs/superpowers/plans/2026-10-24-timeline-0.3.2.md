# Timeline 0.3.2 — the episode's own rows — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship 0.3.2 of the CapCut-style timeline: the music & effects and the original voices can be cut into pieces and shaped (split, trim, delete, a volume line and fades per piece), pieces of the original voices can be switched into the export, and a picture strip of the video helps find scenes. Preview and export play the same thing; every change is one undo step.

**Architecture:** A new table, `stem_pieces`, holds each stem's pieces (`stem` = `music` | `voices`). Pieces are **locked to the picture** (a piece is a window of the stem at the same time; it never moves sideways) and never overlap. An episode with no pieces for a stem has one whole piece, created the first time the pieces are read, so older episodes sound exactly as before (music whole at 0 dB; original voices whole but out of the export). One rule, written twice in lockstep — `backend/app/services/stem_pieces.py` ↔ `frontend/src/lib/stemPieces.ts` — gives a stem's gain at a time (`piece_gain_at`: the piece's volume × its linear fades, 0 between pieces). The export turns it into one `volume` expression per stem (still one input per stem; the music's expression multiplies the 0.3.1 ducking; the original voices are an input only when a piece is switched on); the preview sets the stems' element volumes every frame from the same function. Every edit sends the stem's whole list of pieces (`PUT /jobs/{id}/stem-pieces/{stem}`, validated and clamped on the server), so an undo is one PUT of the list before. The picture strip is a row of small JPEG frames made in the background by the bundled ffmpeg and cached in the episode's folder.

**Tech Stack:** FastAPI + SQLAlchemy async (SQLite/Postgres), ffmpeg (LGPL build: `volume` with `eval=frame`, `fps`, `scale`, the `mjpeg` encoder), pytest; React 18 + TypeScript + TanStack Query + Zustand, lucide-react, `node --test`.

**Spec:** `docs/superpowers/specs/2026-10-23-capcut-timeline-design.md` (approved 2026-10-23). Only its "0.3.2" section and the cross-version sections (look, constraints, anti-goals) are in scope. 0.3.0 and 0.3.1 are built and are the base.

## Global Constraints

- Everything in the 0.3.0 and 0.3.1 plans' Global Constraints still holds. A brand-new table appears through `Base.metadata.create_all` at startup; it still gets an alembic migration (dev, Postgres).
- Existing episodes must sound the same after the update without the user doing anything: the default pieces reproduce today's mix exactly; the export of an episode whose pieces are untouched is unchanged (the whole-music expression is `1`, so no filter is added).
- Pieces are locked to the picture: nothing moves a piece in time; deleting one leaves silence; a trimmed edge can be dragged back out up to the next piece (or 0 / the video's end).
- The track header's music volume (`bgm_volume_db`, baked into `no_vocals.wav`) still applies to the whole track; ducking (0.3.1) applies on top of the pieces.
- Original voices stay out of the export except pieces switched on (`in_export`), drawn in gold. In the preview, a muted original-voices track still plays its switched-on pieces (the export does), so the preview and the export agree.
- Export: no input per piece — one `volume` expression per stem.
- The picture strip is for looking only; making it never blocks the editor (background task, LGPL filters only).
- Constants live in `stem_pieces.py` and are read by the frontend tests: `MIN_PIECE_SECS = 0.1`.

## Review Focus

1. An untouched older episode exports byte-for-byte the same filter graph as 0.3.1 — Task 3 `test_untouched_pieces_add_no_filter`.
2. A list of pieces sent with overlaps, out-of-range or reversed edges, or a moved piece is clamped, not stored as sent — Task 2 `test_pieces_are_kept_inside_their_neighbours`.
3. Preview gain and export expression agree at piece edges and inside fades — Task 2 `test_piece_expression_evaluates_like_piece_gain_at`, Task 5 shared table.
4. Undo of a split / delete / trim of a piece restores the list exactly — Task 6 history helper (one PUT of the before-list).
5. Frame generation for a long episode is bounded (at most `MAX_FRAMES`) and failure-safe.

### Task 2: The piece rules (server)

**Files:**
- Create: `backend/app/services/stem_pieces.py`
- Modify: `backend/app/api/routes/stem_pieces.py` (PUT runs `normalize`)
- Test: `backend/app/tests/test_stem_pieces.py`

**Interfaces:**
- `MIN_PIECE_SECS = 0.1`
- `normalize(pieces, duration: float, before) -> list` — sorted by start; each clamped to `[0, duration]`, at least `MIN_PIECE_SECS` long (dropped otherwise), `volume_db` to `timeline.VOLUME_MIN_DB..VOLUME_MAX_DB`, fades through `timeline.clamp_fades`; a piece overlapping the one before it is cut at that piece's end (never moved); a music piece's `in_export` is always true (music is always exported).
- `piece_gain_at(pieces, t) -> float` — `10^(volume_db/20) × fade_gain_at(piece, t)` for the piece containing `t`, else 0.
- `pieces_volume_expr(pieces, export_only=False) -> str | None` — the same function over `t` as an ffmpeg expression: sum over pieces of `gte(t,a)*lt(t,b)*g*min(1,…fades)`; `None` when the pieces are one whole piece at 0 dB without fades covering `[0, duration]` (nothing to do); with `export_only`, only `in_export` pieces count.

- [ ] **Step 1: Write the failing tests** — `test_pieces_are_kept_inside_their_neighbours`; `test_a_piece_shorter_than_the_minimum_is_dropped`; `test_piece_gain_matches_the_shared_table` (pieces `[0,2] −6 dB fade_out 0.5`, `[3,4] 0 dB fade_in 0.5`: t = 0, 1, 1.75, 2, 2.5, 3, 3.25, 3.9 → 0.5012, 0.5012, 0.2506, 0, 0, 0, 0.5, 1); `test_piece_expression_evaluates_like_piece_gain_at`; `test_untouched_pieces_need_no_expression`.
