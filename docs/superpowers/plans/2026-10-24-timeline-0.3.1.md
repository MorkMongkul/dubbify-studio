# Timeline 0.3.1 — shaping the sound — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship 0.3.1 of the CapCut-style timeline: fades on voice clips, a volume line inside each voice clip, music that dips under voices (ducking), and hearing the mix while dragging the playhead — each heard the same in the preview and the export, each change one undo step.

**Architecture:** Builds on 0.3.0's one timing rule (`backend/app/services/timeline.py` ↔ `frontend/src/lib/clipRules.ts`). Two new rules are written twice and kept in lockstep the same way: a clip's **fade gain** at a time (linear, applied to the clip as trimmed) and the **ducking gain** of the music at a time (a trapezoid over the merged spans of the voiced clips). The export applies them with ffmpeg (`afade` per clip inside the existing `DUB_BATCH` parts; one `volume` expression on the music stem, so still one input per stem); the preview applies the same numbers through Web Audio gain nodes (`useVoicePlayback`) and the music element's volume (`VideoPlayer`). Fades and volume are clip settings (PATCH `/segments/{id}`); ducking is an episode setting (PATCH `/jobs/{id}/ducking`).

**Tech Stack:** FastAPI + SQLAlchemy async (SQLite/Postgres), ffmpeg (LGPL build: `afade`, `volume` with `eval=frame` are there), pytest; React 18 + TypeScript + TanStack Query + Zustand, Web Audio API, lucide-react icons, `node --test`.

**Spec:** `docs/superpowers/specs/2026-10-23-capcut-timeline-design.md` (approved 2026-10-23). Only its "0.3.1" section and the cross-version sections (look, constraints, measurements, anti-goals) are in scope here. 0.3.0 (`docs/superpowers/plans/2026-10-23-timeline-0.3.0.md`) is built and is the base.

## Global Constraints

- Everything in the 0.3.0 plan's Global Constraints still holds (columns need an alembic migration **and** an `add_missing_columns` entry; API shape order models → schemas → route → `types/index.ts` → `client.ts` → `useApi.ts`; one undo step per user change through `historyHelpers.ts`; server / UI / undo state kept apart; LGPL ffmpeg filters only; `Depends(get_db, scope="function")`; no client-supplied server paths; pure frontend logic in `src/lib/*.ts` with only `import type`).
- Preview and export apply the same fade and ducking numbers. Constants live in `timeline.py` and are read by `frontend/tests/*.test.ts` (as `PACE_SECS_PER_CHAR` is in 0.3.0): `DUCK_DB = -8.0`, `DUCK_RAMP_SECS = 0.2`, `VOLUME_MIN_DB = -20`, `VOLUME_MAX_DB = 10` (the transcript panel's range).
- Existing episodes must not sound different after the update without the user doing anything: fades read NULL as 0 (none); ducking is off for episodes analysed before 0.3.1 (`jobs.duck_music` NULL), on for episodes analysed from 0.3.1 on.
- Fades are linear (ffmpeg `afade` curve `tri`), on the clip as trimmed: the fade-in starts at the clip's `start_time`, the fade-out ends at its `end_time`, and `fade_in + fade_out ≤ end − start`.
- Look B (Movelo navy/coral); icons with tooltips; no new status text or spinners (the one-place rule).
- Never run the app against `backend/.env`'s database; never call real AI services. Before every commit run the staged-diff scan; commits end with the Claude co-author trailer the owner asked for.
- Version 0.3.1 is tagged and published only after the user says so.

### Task 2: The sound rules (server)

**Files:**
- Modify: `backend/app/services/timeline.py`
- Modify: `backend/app/api/routes/segments.py` (`_apply_timing`, `split_segment`, `autofit_segment_speeds`), `backend/app/api/routes/tts.py` (`after_new_voice` callers), `backend/app/services/pipeline.py` + `subtitle_pipeline.py` (analysis turns ducking on)
- Test: `backend/app/tests/test_sound_shaping.py`

**Interfaces:**
- Produces in `timeline.py`:
  - `DUCK_DB = -8.0`, `DUCK_RAMP_SECS = 0.2`, `VOLUME_MIN_DB = -20.0`, `VOLUME_MAX_DB = 10.0`
  - `fades_of(seg) -> tuple[float, float]` (NULL → 0)
  - `clamp_fades(seg) -> None` — each ≥ 0; when `fi + fo > length` both scale down by the same factor; called at the end of `clamp_voiced` and `follow_text`
  - `fade_gain_at(seg, t) -> float` — 0 outside `[start, end)`; else `min(1, (t − start)/fi if fi else 1, (end − t)/fo if fo else 1)`
  - `duck_spans(segs) -> list[tuple[float, float]]` — the voiced clips' `[start, end]`, sorted and merged when the gap between two is `< 2·DUCK_RAMP_SECS`
  - `duck_gain_at(spans, t) -> float` — `g = 10^(DUCK_DB/20)`; `d = max over spans of clamp((t − (a − r))/r, 0, 1) · clamp(((b + r) − t)/r, 0, 1)`; returns `1 − (1 − g)·d`
  - `duck_volume_expr(spans) -> str` — the same function as an ffmpeg `volume` expression over `t` (sum of the trapezoids: the merge keeps them apart, so sum = max); `"1"` with no spans
- Split: the first half keeps `fade_in`, gets `fade_out = 0`; the second keeps `fade_out`, gets `fade_in = 0`. Speed change (`rescale_for_speed`) scales both fades by `old_total / new_speed` (they stay on the same words). Analysis (`run_analysis_pipeline`, `run_subtitle_analysis_pipeline`) sets `duck_music = True` when it is NULL.

### Task 6: The preview fades, follows the volume line and ducks

**Files:**
- Modify: `frontend/src/hooks/useVoicePlayback.ts` (Web Audio gain per voice), `frontend/src/components/video/VideoPlayer.tsx` (music ducking)

**Interfaces:**
- Each voice player is routed `HTMLAudioElement → MediaElementAudioSourceNode → GainNode → destination` (one shared `AudioContext`, resumed when playback starts); per frame `gain = storeVolume × fadeGainAt(seg, t) × live` where `live = 10^((liveClipVolume.db − seg.volume_db)/20)` for the clip being dragged, else 1. - `VideoPlayer`: while playing, a frame loop sets the music element's `volume = base × duckGainAt(spans, t)` when `job.duck_music`; `spans = duckSpans(segments)` memoized.
- `previewClip` applies the clip's fades too.
