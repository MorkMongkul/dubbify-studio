# Timeline 0.3.0 — clips follow their voice — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship 0.3.0 of the CapCut-style timeline: a clip is as long as the sound it plays, the preview and the export play exactly the same thing, tracks behave like CapCut's, and the timeline uses icons instead of words.

**Architecture:** One timing rule, written twice and kept in lockstep: `backend/app/services/timeline.py` (server: upgrade, analysis, edits, voice generation, export, Auto-fit, track placement) and `frontend/src/lib/clipRules.ts` + `tracks.ts` (editor: drawing, trimming, dropping, preview playback). A voiced clip plays its voice file from `voice_offset` for `end_time − start_time` seconds at rate `fit_rate`, starting at `start_time`; a clip with no voice is `estimate_secs(khmer_text)` long. The server is the authority for track placement after any change it makes; the editor computes drops and sends them as one batch.

**Tech Stack:** FastAPI + SQLAlchemy async (SQLite/Postgres), ffmpeg (LGPL build), pytest; React 18 + TypeScript + TanStack Query + Zustand, lucide-react icons, `node --test`.

**Spec:** `docs/superpowers/specs/2026-10-23-capcut-timeline-design.md` (approved 2026-10-23). Only its "0.3.0" section and the cross-version sections (look, constraints, measurements) are in scope here.

## Global Constraints

- A column added to an existing table needs both an alembic migration and an `add_missing_columns` entry in `backend/app/core/database.py` (installed apps never run alembic). `add_missing_columns` adds columns with no DEFAULT, so rows that existed before 0.3.0 read NULL; new rows get the Python-side `default=`.
- API shape changes go models → schemas → route → `frontend/src/types/index.ts` → `api/client.ts` → `hooks/useApi.ts`.
- Every editor change the user makes is one undo step through `frontend/src/lib/historyHelpers.ts`.
- Server state in TanStack Query, UI state in `editorStore`, undo in `historyStore` — kept separate.
- ffmpeg: only filters in the LGPL build (`atrim`, `asetpts`, `atempo`, `adelay`, `aformat`, `amix`, `volume` are there).
- Routes take `Depends(get_db, scope="function")`; no DB session open across a long await (commit before synthesis/rendering waits, as the TTS paths do).
- Never accept a client-supplied server path.
- Pure frontend logic lives in `src/lib/*.ts` files with no runtime imports (only `import type`), so `npm test` (node --test, relative `.ts` imports, see `frontend/tests/voiceTags.test.ts`) covers it.
- Preview and export apply the same window rule; nothing changes a voice's speed unless the user or Auto-fit sets it.
- Measured pace: **0.065 s per character** of the Khmer text (Unicode code points); Auto-fit cap **1.25×**; minimum clip **0.1 s**.
- Look B (Movelo navy/coral, speaker-coloured clips); icons instead of words, a tool's name + shortcut in its tooltip; menus keep their words.
- Never run the app, a server or alembic against `backend/.env`'s database: use the test conftest, or `DATABASE_URL=` plus a scratch `DUBIFY_DATA_DIR`.
- Before every commit: `bash .git/movelo-scan-staged.sh`; never commit the root `package.json`/`package-lock.json`, `backend/.env`, `backend/backups/`, `vendor/`, `frontend/src-tauri/binaries/` or `frontend/src-tauri/backend/`. Commit trailer: `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Version 0.3.0 is tagged and published only after the user says so (an earlier release approval doesn't carry over).

## Review Focus

1. Many voices generated at once (batch) on lines of one track: every clip must end up on a track where it overlaps nothing, never moved in time — Task 6 `test_many_new_voices_never_overlap_on_a_track`.
2. Undoing a drop that made the server move other clips: one undo puts every clip back exactly — Task 4 `test_layout_applies_every_change_before_settling`.
3. Trims pushed past the clip's other edge or past the voice (a fast drag, Q/W with the playhead outside): clamp to the 0.1 s minimum and the voice's bounds, never 422 or a negative length — Task 4 `test_trims_never_go_below_the_minimum_length`, Task 8 clamp tests.
4. The app restarted after the upgrade: the conversion must not run twice — Task 3 `test_upgrade_runs_once`.
5. A line with empty Khmer text, or text without any phrase break: lengths and splits stay sane — Task 2 `test_estimate_follows_measured_pace`, `test_split_text_without_a_break_keeps_both_halves_whole`; Task 4 `test_a_voiceless_line_with_no_text_keeps_its_length`.

### Task 2: The timing rules (server)

**Files:**
- Create: `backend/app/services/timeline.py`
- Test: `backend/app/tests/test_timeline_rules.py`

**Interfaces:**
- Consumes: Task 1 columns.
- Produces (all take ORM `Segment`s or any object with the same attributes):
  - `PACE_SECS_PER_CHAR = 0.065`, `MIN_CLIP_SECS = 0.1`, `AUTOFIT_FASTEST = 1.25`, `EPS = 0.001`
  - `estimate_secs(text: str) -> float` — `max(MIN_CLIP_SECS, round(len(text.strip()) * PACE_SECS_PER_CHAR, 3))`
  - `is_voiced(seg) -> bool` — `bool(seg.tts_audio_path) and (seg.tts_duration_secs or 0) > 0`
  - `offset_of(seg) -> float` (None → 0.0), `rate_of(seg) -> float` (None → 1.0), `total_speed(seg) -> float` (`(voice_speed or 1.0) * rate_of`)
  - `max_end(seg) -> float` — `start_time + (tts_duration_secs − offset_of) / rate_of`
  - `clamp_voiced(seg) -> None` — `0 ≤ voice_offset ≤ tts_duration_secs − MIN_CLIP_SECS·rate_of`; `start_time + MIN_CLIP_SECS ≤ end_time ≤ max_end`
  - `follow_text(seg) -> bool` — voiceless line with non-blank `khmer_text`: `end_time = start_time + estimate_secs(khmer_text)`; returns whether it changed. Blank text: untouched.
  - `actor_span(seg) -> tuple[float, float]` — `(source_start, source_end)` when both are set, else `(start_time, end_time)`
  - `overlaps(a, b) -> bool` — `a.start_time < b.end_time − EPS and b.start_time < a.end_time − EPS`
  - `free_lane(segs, seg) -> int` — its own lane if nothing there overlaps it; else the existing lane nearest to it where it fits (ties → the lane below); else `max(lanes) + 1`
  - `settle(segs, changed_ids) -> set[str]` — for each changed clip in start order that overlaps a clip on its lane: `lane_index = free_lane(...)`; returns the ids it moved; never touches times
  - `overrun_target(seg, segs) -> float | None` — the earliest `start_time` among other clips starting after `seg.start_time` (any lane); target = `max(that, source_end)` when `source_end` is set; returns the target only if `seg.end_time > target + EPS`
  - `rescale_for_speed(seg, new_speed) -> None` — `old_vs = voice_speed or 1`, `old_total = total_speed(seg)`; `voice_offset *= old_vs / new_speed`; `end_time = start_time + (end_time − start_time) · old_total / new_speed`; `voice_speed = new_speed`; `fit_rate = 1.0` (caller re-renders, sets `tts_duration_secs`, then `clamp_voiced`)
  - `split_text(text: str, share: float) -> tuple[str, str]` — algorithm below
  - `job_lock(job_id: str) -> asyncio.Lock` (module-level dict of locks)
  - `async settle_job(db, job_id: str, changed_ids) -> set[str]` — the caller commits its own change first; then, holding `job_lock(job_id)`: `db.expire_all()`, load the job's segments fresh, `settle`, commit; returns the moved ids. (Each writer settles after its change is committed, and settling reads fresh rows under the lock, so concurrent voice generation can't leave two clips overlapping on one track.)

`split_text` algorithm: break candidates are the indices just after a space or any of `។ ៕ ! ? , . … ， 。 ！ ？ 、` (excluding 0 and `len(text)`); `target = round(share * len(text))`; take the candidate nearest `target`; `left = text[:b].strip()`, `right = text[b:].strip()`; with no candidate, or an empty side, return `(text, text)`.

`planDrop` algorithm: each moving clip keeps its length and moves by `deltaSecs` (start floored at 0). `onto`: every moving clip moves by the grabbed clip's row delta (clamped to existing rows); if any moving clip would overlap a non-moving clip on its target lane, the drop becomes `insert` at the boundary just below the grabbed clip's target row. `insert` at boundary `b`: the moving clips need `k` new tracks (the span of their rows); use free lane values between `rows[b−1]` and `rows[b]` when the gap allows, else shift every non-moving clip on lanes `≥ rows[b]` by `+k` (emitted as `lane_index` changes) and place the moving clips at `rows[b] … rows[b]+k−1` (above the first row: `rows[0]`, shifting all; below the last: `max + 1`). Returns one change per moving clip plus one per shifted clip.
