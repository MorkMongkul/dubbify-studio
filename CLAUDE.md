# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Movelo Studio (called Dubify Studio until v0.2.0; part of the Movelo brand) — an AI movie-dubbing platform (primarily Chinese → Khmer). Monorepo with a FastAPI backend (`backend/`), a React SPA (`frontend/`), and a Tauri desktop shell (`frontend/src-tauri/`) that runs the backend as a bundled PyInstaller app (a folder in the app's Resources).

## Commands

### Backend (run from `backend/`)

```bash
source venv/bin/activate
uvicorn app.main:app --reload          # http://localhost:8000, Swagger at /docs
pytest app/tests/ -v                   # tests live in app/tests/, NOT tests/
pytest app/tests/test_api.py -v -k test_name   # single test
alembic upgrade head                   # apply migrations
alembic revision -m "description"      # new migration (hand-written, not autogenerate)
```

- No DB setup needed for dev: empty `DATABASE_URL` → SQLite (`khmer_dubber_dev.db`, WAL mode). Production uses Postgres/Neon via `postgresql+asyncpg://`.
- `init_db()` runs `Base.metadata.create_all` at startup, so brand-new tables appear automatically — but a column added to an existing table needs **both** an alembic migration (dev, Postgres) **and** an entry in `init_db`'s `add_missing_columns` lists (`app/core/database.py`): installed desktop apps never run alembic, and without the column every query on that table fails after an update. `add_missing_columns` inspects the table first, so no ALTER ever fails (on Postgres one would abort the transaction). `alembic/env.py` derives its URL from `settings.effective_db_url` (converts async drivers to sync); run it as `venv/bin/python -m alembic` (the `venv/bin/alembic` script has a stale shebang), and never against `backend/.env`'s database.
- Tests use in-memory SQLite with a `get_db` override. `app/tests/conftest.py` blanks the API keys and points `DATABASE_URL`/`UPLOAD_DIR` at a temp dir BEFORE importing the app (env vars override `backend/.env`), so no test can reach real services or the developer's database — tests that need a "configured" key set it with `monkeypatch`. Patch AI calls at the service boundary (`pipeline.transcribe_audio`, `pipeline.translate_batch_with_report`, `asr._call_window`, `tts_client.synthesize`).
- `test_tts_concurrency.py::test_batch_segments_synthesize_concurrently` is flaky (~1 in 5–20 runs, also on older code): every session shares the one `StaticPool` connection, so concurrent workers can roll back each other's pending writes. Fix by moving tests to a file-backed SQLite with a normal pool.

### Frontend (run from `frontend/`)

```bash
npm run dev        # http://localhost:5173 — proxies /api, /health, /uploads to 127.0.0.1:8000
npm run lint       # eslint
npm run build      # tsc -b && vite build
npm test           # node --test tests/*.test.ts — Node ≥ 22.18 runs the TypeScript directly (no test framework)
```

`npm test` covers pure logic kept free of runtime imports (`src/lib/voiceTags.ts`) and checks that the built-in voices' tags are in the tag editor's vocabulary; `tests/` is outside the tsconfig, so it isn't type-checked by the build.

Tailwind, PostCSS and Autoprefixer are devDependencies (build tools; only the CSS they make ships), so `npm audit --omit=dev` covers what the app ships. `npm audit` still flags Tailwind 3's own file watcher (`braces`, which has no fixed version); only Tailwind 4 drops it, so never run `npm audit fix --force`: it installs Tailwind 4, a migration of its own (CSS-first config, renamed utilities, cascade layers that change how the light theme's class remaps in `src/index.css` win).

Run both servers together for dev; the Vite proxy handles all backend calls (frontend uses relative `/api/v1` baseURL).

### Desktop (Tauri)

```bash
scripts/build-ffmpeg.sh aarch64-apple-darwin    # once per arch: LGPL-only ffmpeg/ffprobe → vendor/ffmpeg/<target>/ (bundled by the release script)
scripts/build-fribidi.sh aarch64-apple-darwin   # once per arch: FriBiDi (Khmer subtitle shaping) → vendor/fribidi/<target>/ (required by build_sidecar.sh)
scripts/release-macos.sh aarch64-apple-darwin   # frontend → backend folder (serves frontend/dist) → .app/.dmg; Intel: VENV=<x86_64 venv> … x86_64-apple-darwin
# CI: pushing a v* tag runs .github/workflows/desktop-release.yml (macos-15 + macos-15-intel) → draft GitHub Release; a push to main builds too, only to save the caches (ffmpeg, FriBiDi, Rust) that release builds read — a tag's run can't read a previous tag's caches, so without it every release rebuilt them (Intel 26 min)
# CI runs the two checks below before it makes the draft (a draft exists only when they passed): each build job self-tests its update package and runs check-upgrade.sh against the newest published release on its own chip, and the release job runs verify-release.py --no-self-test. By hand (downloads ~370 MB): gh release download vX.Y.Z -D <dir> -p latest.json -p 'Movelo-Studio-*', then
python3 -I scripts/verify-release.py <dir> X.Y.Z   # names, latest.json, signatures; inside each update package its version, chip and backend self-test (Intel under Rosetta); needs `cryptography`
scripts/check-upgrade.sh <previous release's DMG> <dir>/Movelo-Studio-Apple-Silicon.dmg <new work dir> "<text only the new editor has>"   # the previous release's data opened by the new app, in throwaway folders
cd frontend && npm run tauri dev                # dev shell: uses Vite + a backend you run yourself (no sidecar)
```

How the packaged app runs (`src-tauri/src/lib.rs` ↔ `backend/sidecar_entry.py`): Rust uses port 51734 when it's free, else a random one (the webview keeps saved preferences such as the theme per exact address), and a per-launch instance id, then starts the backend, a PyInstaller one-folder build in `Resources/backend/` (`backend/build_sidecar.sh`; ready in about 1 s; a one-file build unpacked itself on every launch and took 14–35 s), with `PORT`, `DUBIFY_DATA_DIR` (app-data folder), `DUBIFY_LOG_DIR`, `DUBIFY_INSTANCE_ID`, `DUBIFY_APP_VERSION`, `FFMPEG_PATH`/`FFPROBE_PATH` (when ffmpeg is bundled next to the executable) and a PATH that includes Homebrew. It navigates the window to the backend only once `/health/ready` echoes that instance id — at `/?v=<app version>` (`editor_url`), and the backend serves the page with `Cache-Control: no-cache`: the window keeps pages it has loaded, and without both an update went on showing the previous version's screen (and code) until the saved copy expired (0.2.3) — and emits `backend-failed` / `backend-stopped` events that `BackendGate` shows. With `DUBIFY_DATA_DIR` set the backend keeps SQLite, uploads and the user's `settings.env` (written by `PUT /api/v1/settings`; secrets are write-only) in that folder — nothing is baked into the binary. The backend exits when its stdin closes (the app quit or crashed), and raises its open-file limit at start-up (an app opened from Finder gets 256). `movelo-backend --self-test` checks the build can load and shape Khmer; the build runs it. Every ffmpeg/ffprobe call goes through `app/core/binaries.py`.

The public website lives in `website/` (static HTML/CSS/JS, deployed by `.github/workflows/website.yml` to GitHub Pages): `index.html` is the Movelo home page, `studio.html` the Movelo Studio page with the downloads, install help and FAQ (the old one-page site's `#download`/`#install`/`#questions` links are forwarded there by `site.js`). Both follow the Movelo brand kit, and they describe only what the app does today. The Studio page's download buttons link to `releases/latest/download/Movelo-Studio-Apple-Silicon.dmg` / `Movelo-Studio-Intel.dmg`, names that the release job in `desktop-release.yml` gives the DMGs — rename one side and the downloads 404. `website/site.js` also reads the latest release from the GitHub API (version, sizes, "no release yet" state). In-app updates live in `src-tauri/src/updater.rs` (tauri-plugin-updater, native dialogs; driven from Rust so web content gets no updater permission). The app reads `releases/latest/download/latest.json`, which the release job writes with `scripts/updater-manifest.py` from each chip's `Movelo-Studio-<chip>.app.tar.gz` + `.sig`. Builds need `TAURI_SIGNING_PRIVATE_KEY` (+ `_PASSWORD`): CI fails without it, and local builds just skip the update package. The `updater-e2e` cargo feature auto-answers the update dialogs for end-to-end tests only; never enable it for a release. The app icon set in `src-tauri/icons/` is generated from `src-tauri/icons/app-icon.svg` with `npx tauri icon src-tauri/icons/app-icon.svg` (run in `frontend/`; delete the `android/` and `ios/` folders it also writes); it is the Movelo Studio icon from the brand kit in the macOS layout. In-app logos are `src/components/brand/Movelo.tsx`.

The rename from Dubify Studio (app ID `studio.dubify.desktop`) to Movelo Studio (`com.movelo.studio`) moves existing users over on first launch: `src-tauri/src/migrate.rs` moves the old data and logs folders to the new ID (leaving a link at each old location) and renames a copy the updater left in "Dubify Studio.app", then relaunches it; the backend rewrites stored media paths from the old folder (`app/core/data_folder.py`, `DUBIFY_PREVIOUS_DATA_DIR`). Old names kept on purpose: the `dubbify-studio` repository (installed copies' update feed and the website URL), the `DUBIFY_*` variables between shell and backend, and `dubify.db`.

Desktop-only browser APIs go through `src/lib/desktop.ts`, which degrades to a no-op in the browser so components can call it unconditionally (e.g. `chooseVideoSavePath` opens a native Save dialog in Tauri, returns `undefined` in dev). Adding a Tauri plugin needs three edits: `Cargo.toml`, `.plugin(...)` in `src-tauri/src/lib.rs`, **and** a permission for the page that calls it — the editor (served by the backend at `http://127.0.0.1:<port>`) gets its permissions from the runtime capability added in `start_backend` (`CapabilityBuilder`, pinned to that launch's exact origin), the bundled start-up page from `capabilities/default.json`. Miss it and the call fails at runtime only. Web content gets no shell permission (the backend is started from Rust), and a navigation guard keeps the window on those two origins.

## Configuration

All backend settings live in `backend/app/core/config.py` (pydantic-settings, loaded from `backend/.env`). This file is the source of truth for env vars. **All AI is cloud-hosted over HTTPS (HF Spaces + Google AI Studio) — there is no local inference**; every service has a fallback chain that degrades to free/mock implementations when keys or URLs are absent:

- ASR + speaker labels: `app/services/asr.py` (module docstring has the measured reasons). Timing comes from ffmpeg `silencedetect` — never from Gemini's own timestamps, which drift. Clips go to Gemini (`GEMINI_ASR_MODEL`) a whole scene per request (≤40 clips / 300 s), each preceded by a `Clip k (d s):` marker, as FLAC, with structured JSON output; one request both transcribes and labels speakers, and a clip may return several turns (split by character share). Known voices are passed as reference clips (`R1…`) — earlier windows' voices plus the project's named/voiced speakers (`pipeline_common.build_speaker_references`) — and new voices get `SPEAKER_XX` labels not yet taken in the project. Chinese output is normalised to Simplified with OpenCC (Gemini drifts into traditional). Gemini hears clips cut from the episode's **original sound** (`pipeline_common.original_sound_for`: the extracted audio, else the video — the extracted audio is deleted after separation), while pauses are still found on the separated vocals — measured on a real project (3 runs × 5 episodes): Gemini's man/woman call right for 17 of 19 speakers from the original sound vs 13 of 18 from the vocals, transcription as good or better (why isn't known: the voices' pitch is the same in both; excited young men in these dramas really speak at ~240 Hz — the original sound's "130 Hz" was the music's bass). Each reference voice also says who it is ("a man, 20s", from the voice the user chose) and up to 8 of the character's lines from other episodes (`REFERENCE_SAID`): on a real project the right character for 36–42% of lines from a voice clip alone, ~47% with these, 55% together with clips from the original sound (young men's voices sound alike; what they say tells them apart). Each turn says who the voice sounds like (`voice`: man/woman/boy/girl, `asr.VOICES`); `ensure_speakers` keeps it on a speaker whose gender isn't known yet, and "Choose for me" (`auto_voice._speaker_kind`) and the translation's WHO IS SPEAKING use it before pitch. A clip with more than `MAX_CHARS_PER_SECOND` (20) characters per second is asked for again — Gemini once looped to 1,543 characters for a 90 s episode. Requests have wall-clock timeouts, retry/backoff on 429/5xx, split-in-half retry, and a circuit breaker. `app/services/diarizer.py` (MOSS) is unused except for the shared `DiarizedSegment` type.
- `TRANSLATION_BACKEND`: `"gemini"` (needs `GEMINI_API_KEY`) or `"deep"` (free Google Translate). Failure order in `translator.py`: temporary Gemini errors (429/5xx/network) are retried with backoff → lines missing from Gemini's answer are asked for again → only then the Google Translate fallback, which is batched, throttled and retried (that free endpoint rejects bursts). Lines nothing could translate stay empty; the transcript shows "N lines have no translation" with **Translate missing lines** (`POST /jobs/{id}/translate` → `pipeline.run_translation`), which fills only empty lines and never overwrites an edit, even one typed while it runs. Translation uses a full Flash model (`GEMINI_MODEL`, default `gemini-3.6-flash`; Flash-Lite is only the last fallback — its Khmer needed fixing line by line). Besides the lines (each tagged `[SPEAKER_XX]`) and the Story notes, the prompt gets WHO IS SPEAKING (`pipeline_common.translation_cast`, at all three call sites): per tag the user's name for it, the Story character linked to it, and man/woman + age from the voice the user chose — never from pitch: excited young men in these dramas speak at 230–250 Hz, and on a real project the pitch called 4 of 5 men women or children (the same measurement `auto_voice` picks voices with). Khmer politeness (បាទ for a man, ចាស for a woman) and pronouns depend on it. A later batch of a long episode also sees the previous `EARLIER_LINES` lines with their translations. And it learns from the team: `pipeline_common.translation_memory` gives the (source, Khmer) pairs of the project's other episodes — only checked Khmer: lines the team voiced or approved, or episodes marked finished (an unreviewed episode holds Gemini's own draft), and `translator.pick_examples` shows them as examples — all of them up to `MEMORY_EXAMPLES`, else each line's most similar ones, then the most recent (measured leave-one-episode-out on a real project: chrF 33.1 without, 35.3 with all, 34.1 with the 20 most similar).
- **Story notes** (`app/services/story_notes.py`, `story_learning.py`, routes `app/api/routes/story.py`): one JSON document per project (`projects.story_notes`) — the user's intro plus the characters, words to keep, a summary per episode and the tone that the Assistant's model learns from the episodes the user marks finished (`jobs.finished_at`, `PATCH /jobs/{id}/finished`). Learning runs in the background, one run per project, a few episodes per request, with no DB session open during the Gemini call; each answer is merged into the notes as they are by then (`merge_learned`), and nothing the user wrote or corrected (`by: "you"`) is ever changed, nor an item they removed added back. Translation (all three call sites, via `pipeline_common.translation_story`) gets a bounded block (`for_translation`: intro, tone, characters, words, the summaries of the 5 previous episodes); the Assistant gets all of it in its system instruction. The Story tab (`StoryPanel.tsx`) shows and edits them, and learning's progress shows only there.
- **Gemini model names**: every Gemini call goes through `app/services/gemini_models.py` — never build a `generateContent` URL from a settings value. Google retires model versions ("no longer available to new users" — this broke translation with `gemini-2.5-flash-lite` and earlier the Assistant), and a retired model can stay in the model list. Each job (translation/asr/chat/tts) tries the Settings model (empty = the built-in default), then Google's `-latest` aliases, then the newest listed model of the same kind; a 404 / "not available" switches models for the session and logs it. Settings → AI models (`GET /api/v1/settings/models`, `POST /api/v1/settings/models/test`) lists models per job for the saved key and checks a choice with a real request. Newer Gemini speech models return WAV, older ones raw PCM — `tts_client` handles both.
- TTS: `VOXCPM2_API_URL` (a Gradio app, e.g. an ephemeral Colab share URL) → public HF Space (`VOXCPM2_HF_SPACE_FALLBACK`) → Gemini TTS → mock silent audio. Silent mock audio is only accepted in pure mock mode (no engine configured at all — the HF Space counts); otherwise it is a failure and nothing is saved. Both synthesis paths go through `tts._render_segment_audio`, which writes to a temp file and only replaces `seg_<id>_raw.wav` (what effect changes re-render from) on real success. A new voice (`tts._render_segment_audio`) has the silence the engine puts around the words trimmed before it becomes the raw clip (VoxCPM starts each voice with ~0.6 s — measured on a real project, trimming made 48 of 69 voices fit their line instead of 10, and it's why voices came in late; the public HF Space sends MP3 under the clip's `.wav` name, so the trim always writes a real WAV to a separate file and swaps it in — rewriting it in place emptied the voice in 0.2.8; a voice that still comes back empty or unreadable is a failure, never a 0-second clip), and its level is decided once (`voice_level.level_new_voice`): the loudness of the original line where the actor spoke (`timeline.actor_span`; voiced frames of the separated vocals; 0 when separation failed), stored as `Segment.level_gain_db` (column 0.2.8: alembic + `add_missing_columns`). Every clip render (`voice_level.render_clip`: new voice, volume/filter/speed change, Auto-fit) applies that gain plus the user's volume, never peaking above -1 dBFS; a voice made before 0.2.8 has no stored gain and renders exactly as before (re-levelling an old voice on its first touch put it ~10 dB off its untouched neighbours). The line's times and effects are read again after synthesis — it takes seconds to minutes and the timeline isn't locked. A new voice sets its clip (`timeline.after_new_voice`): the clip starts where the line starts and is as long as the voice, and the text it was made from is kept (`voice_text`); a clip that then runs into the next one on its track moves to another track, never in time (see Timeline timing). Auto-fit (`POST /jobs/{id}/segments/autofit`) only speeds up voices that run into a later line, just enough to end before it, never above 1.25× (`timeline.AUTOFIT_FASTEST`), never slowing one down or lowering a speed the user set. Telling translation each line's length was measured and gave no gain. Design voices are baked only from VoxCPM output.
- Separation: HF Space only (`SEPARATION_HF_SPACE`) → no-op (original audio used as both stems). The fallback leaves `separation-unavailable.txt` (with the reason) next to the stems, so `JobResponse.stems_separated` stays `false` and the transcript offers **Try again** (`POST /jobs/{id}/separate` → `pipeline.run_separation_retry`). The retry separates into a temporary folder and swaps the stems in only on success, deletes `no_vocals_raw.wav` (the music level is rendered from it, `source_separator.render_bgm_volume`) and re-applies the job's `bgm_volume_db`; the job returns to the status it had (an interrupted retry is settled the same way by `recover_orphaned_jobs`).

This means the entire pipeline runs end-to-end on a laptop with zero keys (mock mode) — useful for testing API flow. Translation never stores the source text as a "translation": `translator.translate_batch_with_report` leaves failed lines empty and counts fallback/failed lines, which the pipelines put in the job's warning. The pyannoteAI, local Whisper, local Demucs, and Modal REST backends were removed (July 2026) — do not reintroduce `DIARIZATION_BACKEND`, `SEPARATION_BACKEND`, `PYANNOTEAI_TOKEN`, `WHISPER_API_URL`, `VOXCPM2_BACKEND`, or `VOXCPM2_API_KEY`.

## Architecture

### Pipeline (backend)

The dubbing pipeline is **two user-controlled stages plus on-demand steps**, orchestrated in `app/services/pipeline.py` and run as FastAPI background tasks (asyncio, in-process — no job queue):

1. **Stage 1** (`run_pipeline`, on video upload): ffmpeg audio extraction → vocal/BGM separation → stops at `STEMS_READY` status, waiting for the user.
2. **Stage 2** (`run_analysis_pipeline`, user clicks Analyze): transcription (no diarization, see `app/services/asr.py`) → translation → creates `Segment` rows → `COMPLETED`.
3. **TTS + mix** are separate endpoints (`app/api/routes/tts.py`), triggered per-segment or per-job; final mix composites TTS audio, BGM stem and the media clips via ffmpeg (`audio_extractor.mix_dubbed_audio`).

`app/services/subtitle_pipeline.py` is an alternative Stage 2 that uses embedded/uploaded subtitle tracks instead of ASR (also skips diarization, same as the main ASR pipeline). Shared helpers (job status updates, speaker creation, orphaned-job recovery on startup) live in `pipeline_common.py`. `JobStatus` in `app/models/models.py` enumerates every stage.

### Timeline timing (0.3.0)

One rule, written twice and kept in lockstep: `backend/app/services/timeline.py` (analysis, the upgrade, edits, voice generation, Auto-fit, the export, track placement) ↔ `frontend/src/lib/clipRules.ts` + `tracks.ts` (drawing, trims, drops, preview playback); `frontend/tests/clipRules.test.ts` reads the constants from the Python file. **A clip with a voice plays its voice file from `voice_offset` for `end_time − start_time` seconds at `fit_rate` (on top of the speed baked into the file, `voice_speed`), starting at `start_time`** — so it is exactly as long as the sound it plays. The preview (`hooks/usePreviewAudio.ts` + `lib/audioPlan.ts`, below) and the export (`audio_extractor._render_dub_part`: `atrim` + `atempo` per clip, still `DUB_BATCH` parts) apply the same window; nothing speeds a voice up on its own. Dragging a voiced clip's edge cuts sound (`trimStart`/`trimEnd` ↔ `clamp_voiced`), never changes its speed; a speed change keeps the same words cut (`rescale_for_speed`). **A clip with no voice yet is as long as its Khmer text takes to say**: 0.065 s per character (Unicode code points, `PACE_SECS_PER_CHAR`; measured 2026-10-23 on 18 voices made since 0.2.8, median error 9% — re-measure once more voices exist), re-estimated whenever its text is saved (`follow_text`); its edges can't be dragged. Editing the Khmer text keeps the voice (the clip shows it was made from older text: `voice_text ≠ khmer_text`). `source_start/source_end` are where the actor spoke (the detected span; the span a line had at the upgrade; none for a line added by hand) and stay put when the clip moves — they aren't drawn (a bracket under each clip read as clutter once clips moved; removed 2026-10-24); everything that needs the actor's timing (voice choice by pitch, speaker references, a new voice's loudness, mapping a fresh transcription) reads `timeline.actor_span`. Red stripes mark where a voice runs into a later line where the original didn't overlap. **Tracks**: clips never overlap on one track; a clip that grows into another (a voice, a speed, a text, the upgrade) moves to the nearest track where it fits, never in time (`settle`); the server settles after every change it makes (`settle_job`, under a per-job lock, after the change is committed, so concurrent batch voices can't collide), and the editor plans drops with the same rules (`tracks.planDrop`) and sends them in one request (`PUT /jobs/{id}/segments/layout`); an empty track isn't drawn. Every timeline change is one undo step (`recordLayoutChange` carries the clips the server moved too). Episodes from before 0.3.0 (`jobs.timeline_version` NULL) are converted once at startup (`timeline.convert_old_jobs`): a voice the old app sped up to fit gets that speed as `fit_rate` (up to 2×), so they sound the same.

**Track switches (like CapCut's track headers)**: each voice track's header shows its kind — audio (a sound-wave icon) once one of its lines has a voice, text (a T) before — and lock and, for audio, mute (`lib/trackFlags.ts`; the hide switch went with the burned-in subtitles in 0.4.0 — it only hid subtitles). They're saved per episode in `jobs.track_flags` (JSON keyed by lane_index, only tracks with a switch on; alembic + `add_missing_columns`; `PUT /jobs/{id}/track-flags`, one undo step) and pruned when a track has no clips. Locked: the editor refuses every edit of its clips (drag, trim, fades, volume line, split, Q/W, speed, new voice, delete — a group drag leaves them), a drop onto it becomes a new track (`planDrop(..., locked)`), and the server never moves another clip onto it (`timeline.free_lane`). Muted: its voices aren't played, scrubbed or exported, and don't dip the music (`timeline.export_lines`). A drop that inserts a track moves the switches of the tracks below (`laneShift`/`shiftSwitches`, sent with the layout request and undone with it); a clip the server moves keeps to tracks muted like its own (a new track inherits them); Tidy packs around switched tracks. Exporting with a muted track, a hidden or muted media track, or an episode's old overlays first lists what will be left out (`exportWarnings`, `mediaExportWarnings`, EditorPage).

**Shaping the sound (0.3.1)**, the same way in lockstep: fades are clip settings (`fade_in_secs`/`fade_out_secs`, linear, on the clip as trimmed, never longer together than the clip — `clamp_fades`; split gives each half its outer fade, a speed change keeps them on the same words), applied by the export's `afade` inside each clip's window and by the preview's fade automation per voice (`audioPlan.fadePoints`, with a level gain = editor volume × a volume line being dragged). The volume line inside a voice clip sets `volume_db` (−20…+10 dB; `VOLUME_MIN_DB/MAX_DB`; the clip panel keeps only the voice filter — volume and speed are set on the timeline). Like CapCut, every waveform is drawn at the sound's real level (absolute peaks, never scaled to the clip's own loudest point — `lib/waveform.ts`), a dragged line moves 2 px per dB from where it was grabbed (`volumeAfterDrag`: a 3 px dead zone, every whole dB reachable; double-click: back to 0 dB) and scales the bars live — previewed through `editorStore.liveClipVolume` (each moved clip's target dB) and saved on release — and bars more than 0.3 dB past the export's −1 dBFS limit (`CEILING`, = `voice_level.CEILING_DB`, checked by `npm test`) turn red; music and original-voices pieces draw their own part of the stem from its levels, decoded once at 8 kHz (`hooks/useStemPeaks.ts`; a piece is two SVG paths, `PieceWave`), so the music row has no track volume slider, and original voices not kept in the export draw dimmed. A volume line dragged, or Speed › chosen, on a clip that is part of a multi-selection applies to every selected voice (`clipRules.selectionTargets`; volume moves all by the same dB, `shiftedVolume`, so their balance stays; one undo step for the clips that saved — `lib/batchSave.ts`, four at a time since each change re-renders a voice); a timeline Shift+click right after a plain click selects both, while that clip is still the active one (`toggleInSelection`, `TimelineEditor.handleShiftSelect`, `editorStore.selectionAnchorId`; the transcript's checkboxes stay a plain toggle). The music dips under the voices (`jobs.duck_music`; NULL = analysed before 0.3.1 = off, so older exports don't change; analysis turns it on): `DUCK_DB` −8 dB with `DUCK_RAMP_SECS` 0.2 s ramps over the voiced clips' merged spans (`duck_spans`/`duck_gain_at` ↔ `lib/ducking.ts`), exported as ONE `volume='…':eval=frame` expression on the music stem (`duck_volume_expr`, still one input per stem) and previewed by the music element's volume each frame (`VideoPlayer`). Hear while dragging (`editorStore.scrubAudio`, the headphones toggle) plays 120 ms snippets of that mix while the playhead is dragged (`hooks/useScrubAudio.ts`). The shared numbers are tested on both sides with the same table (`test_sound_shaping.py` / `tests/ducking.test.ts`).

**The episode's own rows (0.3.2)**: the music & effects and the original voices are cut into pieces (`stem_pieces` table: `stem` music|voices, start/end, volume, fades, `in_export`; rules in `app/services/stem_pieces.py` ↔ `src/lib/stemPieces.ts`, a shared gain table tests both). Pieces are locked to the picture — never moved; deleting one leaves silence; a trimmed edge can be dragged back out up to the next piece. An episode starts with one whole piece per stem (made the first time `GET /jobs/{id}/stem-pieces` runs, once `duration_secs` is known), so an episode nobody cut exports exactly as before: `pieces_volume_expr` returns None for one whole untouched music piece and for no switched-on voices piece, and no filter or input is added. Every edit sends the stem's whole list (`PUT /jobs/{id}/stem-pieces/{stem}`, clamped by `normalize`), so an undo is one PUT of the list before (`recordPiecesChange`). The export applies one `volume='…':eval=frame` expression per stem (the music's before the 0.3.1 dip; the original voices — `vocals.wav` — become an input only when a piece is switched on, `in_export`, drawn gold). The preview sets the stems' levels every frame from the same gain (`stemLevelAt`, VideoPlayer's `stemLevel`, through a gain node, so a piece above 0 dB is heard above the file's level); a muted original-voices track still plays its switched-on pieces, as the export does. `jobs.stem_pieces_made` marks that the pieces were given: after that a stem with no pieces is one the user emptied — silence in the preview and the export, never recreated. With a piece selected, S / ⌘B / ⌫ act on it only (`keysActOn`). Delete a job's or project's `stem_pieces` with its segments (Postgres enforces the FK). The picture strip (`app/services/picture_strip.py`, `GET /jobs/{id}/frames`): JPEG frames every `frame_interval` s (≥ 1 s, at most `MAX_FRAMES` 600) made in the background once per job per run with `fps` + `scale` + mjpeg (LGPL build) into `<job>/frames/` (`done.json` written last); the editor polls until ready.

**Preview playback (0.3.1)**: WebKit — Safari and the desktop app — stalls a playing media element whenever it is touched: a seek stalls it ~0.3–1 s, and a speed change stops a video outright (12 changes in 6 s: it moved 0.18 s; measured 2026-10-24). Media elements kept in step with the video by seeking or speed nudges cut the sound and froze the picture there, while Chrome played smoothly. So the preview plays like an editor (`hooks/usePreviewAudio.ts`, pure math in `lib/audioPlan.ts`): every voice and both stems are decoded into memory (`decodeAudioData`; the open episode's stems ≈50 MB each; every voice of the episode queued as it opens, `LOADING_AT_ONCE` at a time from the playhead on — `audioPlan.loadOrder` — and those within `LOAD_AHEAD` s at once) and started as `AudioBufferSourceNode`s on one AudioContext clock at exact offsets; the engine starts and pauses the video itself. Pressing play waits (at most `READY_WAIT` s) until the sounds of the first `READY_SPAN` s are loaded — right after an episode opens they took ~2 s, and voices then came in late, missing their first words. A clip or stem whose sound changes while it plays (a speed, a filter, a trim, a music level) plays on until its new sound is loaded, then the two cross over in `SWAP_SECS` (12 ms) — stopping it first left a gap after every edit. The video is moved only when the playhead was moved (`transport.seekVideoTo`: a store time that isn't the one the video itself last reported — exactly there, however close); the old rule ("more than 0.3 s from the store") jumped the video back when the page was busy for a moment, e.g. redrawing after an edit. **Never seek or change the speed of the playing video or any player**: when picture and sound drift apart beyond lip-sync limits (`lib/playbackSync`: sound 45 ms early / 125 ms late), the sound — which restarts instantly anywhere — starts again from where the picture is. Every start — play, a seek or a stall while playing (`seeked`/`waiting`), a new speed — goes one way (`start`/`restart`): the engine holds the picture (paused; `heldByEngine` keeps VideoPlayer from treating it as the user's pause), waits for the sounds and a playable picture, starts the sound at once from where the picture is, and times both so the first sound is heard as the first frame shows, whichever needs longer (`startTimes`: the sound needs `LEAD + latency` — output delay = `baseLatency + outputLatency`, Bluetooth earbuds ~0.4 s — the picture `videoDelay`; the slower one goes at once and the other waits). How long the picture takes to start moving after `play()` differs by machine — 20 ms in one WebKit, ~0.5 s in the user's Safari, where a fixed guess made every start correct itself with a cut — so it is learned from the first look after each start (`learnedDelay`) and kept in localStorage per output delay. Drift is measured only on the frames shown (`requestVideoFrameCallback`: `mediaTime` at `expectedDisplayTime`; right after a start Safari's `currentTime` ran ~0.3 s ahead of them), and a correction moves the sound with the same 12 ms crossover (`shiftAnchor`, `crossOver`), never a stop. The `<video>` is muted (not just volume 0) and loads ahead (`preload="auto"`). A voice at `fit_rate` > 1 is fetched already stretched with the export's own `atempo` (`GET /segments/{id}/voice?rate=`, `audio_extractor.voice_at_rate`, cached in the voice's `preview/` folder per file version and speed), because a buffer's `playbackRate` would change its pitch; the J/K/L shuttle's 2×/4× does change pitch. The double-click preview of one clip (`previewClip`) and hear-while-dragging (`useScrubAudio`) still use media elements.

**Media (0.4.0)**, like CapCut's Media, replaced the Elements tab (`components/panels/MediaPanel.tsx`). A project's images and videos (`media_assets`; `POST/GET /projects/{id}/media`, `DELETE /media/{id}` — its clips leave every episode and every template) are probed on upload (`media_assets.probe_asset`: transparency from the pix_fmt or WebM's alpha tag; HEVC-with-alpha and WebM alpha can't be read by the bundled LGPL ffmpeg, so `alpha_kept` is false and the tile says so; animated WebP is refused) and prepared in the background (`make_preview`): a thumbnail, and for a video a **preview copy — H.264 with the colour picture stacked over its alpha matte** (one double-height frame, long side ≤ 1280, only ever shrunk; `h264_videotoolbox` in the bundled build) and its sound as `audio.m4a`. An episode's clips (`media_clips`; switches in `jobs.media_track_flags`, separate from the voice tracks') are edited as one list (`GET/PUT /jobs/{id}/media-clips`, like the stem pieces; `media.normalize` keeps clips inside the episode, a video never past its own end, never two on one track; a moved box teaches its media `last_box`), rules in `app/services/media.py` ↔ `src/lib/media.ts`, editing in `hooks/useMediaEditing.ts`. Media tracks sit **above the picture strip** (`timeline/MediaTracks.tsx`); the top track (highest lane) is drawn over the ones under it, so a clip never changes track by itself: a drag runs the voice tracks' `planDrop` with the top track as row 0 and numbers the tracks again (`planMediaDrop`; switches follow their track), a tile dropped from the panel lands at the pointer (`dropNewClip`), a tile's + at the playhead on the top free track (`addAt`), ⌘V at the playhead (`pasteClips`, never onto a locked track), ⌘D right after the clip; a video can be trimmed but never stretched past its own end, an image stretches; split keeps a video playing on (`splitClip`); a clip with sound has a volume line (−20…+10 dB). Selecting media (`editorStore.selectedMediaIds`) clears the voice clips' selection and vice versa, and S/⌘B/⌘D/⌫/⌘C/⌘V then act on media; the clipboard (`mediaClipboard`) survives switching episodes of the project. Each change is one PUT and one undo step (`recordMediaChange`). **Preview** (`video/MediaCanvas.tsx`, `lib/mediaGl.ts`): one WebGL canvas over the frame draws the clips under the playhead in track order — a video's colour from the top half of its preview copy, its alpha from the bottom half's red, because a `<video>` on screen draws partly transparent areas opaque in WebKit. Each video clip near the playhead has a hidden player (opacity 0 but frame-sized: WebKit doesn't advance a video it thinks is off screen) run by `mediaVideoStep`: parked on its first frame `PRELOAD_SECS` (2) ahead with its speed set, started on the main video's frame (`requestVideoFrameCallback`) when its clip starts, put back at most once a second when more than `DRIFT_SECS` (0.3) off, on the exact frame when stopped (seeks coalesced). The selected clip gets a box to move it and corners to resize it with its shape kept (`resizeBox`); the player's controls sit above it. Its sound plays on the preview's clock like a voice (`usePreviewAudio` `mediaSounds`, `audioPlan.mediaSoundStart`; level = volume × `volume_db`, the file itself is raw), never dipped by the music. **Export** (`mix_dubbed_audio(media=…)`, built in `routes/tts.py`): the original file (ProRes 4444 keeps its alpha), **one input per video clip** (`-ss`/`-t`; sharing one with `split` held 1.14 GB) and one per image (split when reused), `setpts`→`scale`→`format=yuva420p`→`overlay … enable=between(t,…)`, lower tracks first; its sound is made stereo at full level, `volume`/`adelay`, and mixed into the dub after the dub's pan, before the music. At most `MAX_EXPORT_CLIPS` (32) clips (the editor says so before exporting). Hidden track: no picture; muted: no sound. **Templates** (`media_templates`; the owner asked): *Save* stores the open episode's clips; *Apply* is by hand only — a new upload must be dubbed first — and adds them beside what's there (`media.fit_template`: a clip past a shorter episode's end moves earlier; media deleted since is skipped and reported), one undo step. The old Elements — subtitle style, blur box, logo (`overlays`) — are no longer drawn or exported and no longer applied to new episodes; their rows are kept (`MediaClipList.old_overlays`, which the export window mentions). Measured 2026-10-24 with the owner's Locora sponsor card on a copy of the real project: upload → ready 3.4 s; the preview's semi-transparent panel within a median 7 of the correct blend, the export's within 1. Playwright's headless WebKit draws nothing for that project's own `source.mp4` (Safari does): re-encode a scratch copy to check pictures there.

### Data model

`Project` → `Job`s → `Segment`s + `MediaClip`s (the old `Overlay` rows are kept but unused since 0.4.0); `Speaker`s, `MediaAsset`s and `MediaTemplate`s belong to the project. `Voice` is a **workspace-global** voice library (not project-scoped). **Built-in voices** (`app/services/builtin_voices.py`) ship in `app/assets/builtin_voices/` (FLAC + `manifest.json`, made from the voice-casting sessions): on startup each is installed as an ultimate voice (reference clip in `uploads/voices/<id>/` + transcript) with a fixed `builtin-…` id, so speakers keep them across updates. The voices routes refuse to edit or delete them (403), and a re-recorded voice gets a new id; a voice a re-cast replaced is listed in the manifest's `retired`, and startup removes it unless a speaker or line still uses it. Their names (Sino-Khmer, Latin letters) and tags (`gender`, `age_group`, `personality`, `roles`) also come from the manifest, which is the source of truth for them (the casting script keeps them on a re-run). Every voice, built-in or the user's own, can carry those tags; `app/services/voice_tags.voice_section` turns them into the Voices-tab section (`VoiceResponse.section`), and `src/lib/voiceTags.ts` groups voices for the tab and the voice browser (no section → "My voices" for the user's own, "Other voices" otherwise). Voices are chosen in one place, `src/components/voices/VoiceBrowser.tsx` (search, section filters, a player and "Used by" for each voice): it slides over the Speakers panel, and opens in a window for a new speaker or a single line; never go back to a plain `<select>` of 67 voices. `POST /voices/{id}/copy` makes an editable copy of any voice with its own clip. A character the detection gave two labels is fixed with **Same person as…** on a Speakers card (`POST /speakers/{id}/merge`): all its lines in every episode move to the other speaker, it is removed, the Story character linked to its label follows (`story_notes.relink_speaker`); undo is one call (`POST /speakers/{id}/unmerge`, `recordSpeakerMerge`) that brings it back as it was — voice and whether the app picked it, heard gender and age — with the moved lines still on the other speaker and its Story characters. Voice resolution precedence for TTS (`routes/tts.py _resolve_voice`): `Segment.voice_id` override → `Speaker.voice_id` → a speaker without one gets a built-in voice picked and saved (`app/services/auto_voice.py`: man/woman/child by the voice Gemini heard (stored on the speaker), else by the median pitch of the actor's lines in the separated vocals, unused in the episode, never retired; `Speaker.voice_auto` marks it, and it doesn't make the speaker confirmed until lines were voiced with it) → legacy `Speaker.voice_design_prompt` only when no built-in voices exist. A line without a speaker gets a fixed voice by its own pitch. Never voice a line from a blank description: that gives a different random voice per line. Media boxes (like the old overlays) are stored as **fractions (0–1) of the video's frame** so the preview canvas and the full-resolution ffmpeg export map identically.

### Frontend state

Three distinct state layers — keep them separate:

- **Server state**: TanStack Query only. `src/api/client.ts` is the single axios layer (all endpoints), `src/hooks/useApi.ts` wraps each one in a query/mutation hook. Job progress is polled via `refetchInterval`.
- **UI-only editor state**: `src/store/editorStore.ts` (Zustand) — playback, timeline zoom, selection, plus `segmentPositions`: only the edits still in flight (a drop or trim waiting for the server, unsaved text), laid over the server's segments by `lib/segmentOverlay.ts mergeOverlay` and dropped once the server answers — the voice (every `tts_*`/`voice_*` field but `voice_offset`) always comes from the server.
- **Undo/redo**: `src/store/historyStore.ts` — because editor state is server-persisted, each history entry is a pair of async inverse **API calls**, not local snapshots. Any new editor mutation that should be undoable must push an entry via the helpers in `src/lib/historyHelpers.ts`; the `isApplying` guard prevents undo/redo from re-recording itself.

The editor IS the app (CapCut-style single window, Aug 2026): `src/pages/EditorPage.tsx` renders every route (`/`, `/projects/:projectId`, `/projects/:projectId/jobs/:jobId`; anything else redirects to `/`). A far-left icon rail (`src/components/layout/EditorRail.tsx`) drives a dynamic dock panel via `railTab` in editorStore — tabs: Projects (episodes are listed inline under each project) / Speakers / Media / Voices / Story / Assistant, implemented in `src/components/panels/*`. Settings is a window over the editor, not a tab: the gear at the foot of the rail or ⌘, opens `src/components/settings/SettingsDialog.tsx` (`settingsOpen` in editorStore), which `App` renders outside the keyed routes (a navigation can't reset it) with everything else `inert` while it's open. Groups on the left each save their own fields (`src/lib/settingsDraft.ts`; a blank key box is never sent, because an empty key removes the saved one), and no key reaches the editor's shortcuts or the system's Undo (in the desktop app an unhandled ⌘Z goes to Edit › Undo, which undoes typing anywhere on the page). The Assistant's "this line" is `editorStore.assistantLineId`, set when a transcript line's text box gets focus — not on hover, since `activeSegmentId` follows the mouse (and playback); it goes with a chat message as `line_id`, and the backend keeps a snapshot (`chat_messages.line_ref`) that replays as a `[This line — …]` prefix, so a reopened chat still knows the line. A project has several Assistant chats (`chat_threads`, `chat_messages.thread_id`), each sending only its own messages to Gemini: the first message starts and names a chat (`chat_agent.thread_title`), History lists them newest first, and messages saved before threads become one chat the first time the project's chats are listed (`adopt_unthreaded`); `editorStore.assistantThreads` remembers the open chat per project. There are no standalone pages or nav sidebar anymore. EditorPage arranges three areas around the `TimelineEditor` — the dock panel, the player (`VideoPlayer` + `OverlayCanvas`) and the `TranscriptPanel` — in one of four layouts like CapCut's (`lib/layouts.ts` `layoutPlan`, tested by `npm test`): Default (panel, player, transcript over the timeline), Vertical (the player as tall as the window on the right and the transcript in the middle, for 9:16 episodes), Transcript (the transcript as tall as the window) and Panel (the panel as tall as the window). The top bar's `LayoutMenu` picks one (its icons are drawn from the same plan) and Reset layout restores the widths; the choice is kept in localStorage (`lib/layoutStorage.ts`). An area keeps its width across layouts, a hidden transcript leaves no gap, and switching pauses playback (the player remounts in its new place). Rail tabs must never navigate (an auto-navigate effect bounces `/projects/X` to its latest job); only rows inside panels navigate. `railTab` deliberately lives outside `DEFAULT_STATE` so `resetEditor()` (fired per session switch) can't wipe it; routes are keyed by pathname, so EditorPage remounts on every navigation and re-derives the tab on mount. Path alias `@/` → `src/`.

A running step shows its progress in **one place** (wording and the estimate in `src/lib/jobProgress.ts`, tested by `npm test`): the transcript panel — a full view before the episode has lines, a thin bar above them after (speaker detection, re-analysis, missing translations, separating again) — with Stage 1 in the video's place, and the top bar only while the transcript panel is hidden. The full view is a progress ring (`components/ui/ProgressRing.tsx`, `components/progress/JobProgressRing.tsx`: a percentage, a title with a light sweeping across it, `.shimmer-text`; ✓ Done for a moment when a wait ends well, `hooks/useDoneFlash.ts`). Its percentage is an estimate, because no step can report its own progress (they run on outside services, and a short episode goes to Gemini in one request): `app/services/job_clock.py` notes when each step began (in memory, from a listener on `Job.status`), `JobResponse.step_elapsed_secs` reports it, and `stagePercent` fills each step's slice of the ring at the pace it usually takes for the video's length (`RING_STEPS`, measured on real runs — recalibrate there), slowing near the end and waiting rather than going backwards or saying 100% early. The upload's slice is its real progress (axios `onUploadProgress`). Don't add spinners to other panels (users found four copies of one status redundant). The status can't tell speaker detection from a re-analysis (both `diarizing`), so `useAnalyzeJob` / `useDetectSpeakers` / `useTranslateMissing` record what was started in `editorStore.jobActions` (outside `DEFAULT_STATE`); after a reload the wording falls back to what the status alone supports.

### Types must stay in sync

Backend Pydantic schemas (`app/schemas/schemas.py`) ↔ frontend types (`src/types/index.ts`) are maintained by hand. When changing an API shape, update: models.py (+ migration) → schemas.py → route → types/index.ts → client.ts → useApi.ts.

## Gotchas

- `max_speakers` (the "spk" input next to Analyze) is plumbed end-to-end but ignored — Gemini decides how many voices it hears.
- Stage 2 can re-run (`POST /jobs/{id}/analyze` from `stems_ready`, `completed` or `failed`): the route claims the job under a row lock (409 when busy), and the pipeline swaps segments atomically (`pipeline_common.replace_job_segments`) — a failure keeps the old segments and leaves the job COMPLETED with a message (`restore_or_fail_job`). `POST /jobs/{id}/detect-speakers` relabels existing segments only (fresh transcription mapped by time overlap, `asr.labels_for_spans`); text, edits and audio are untouched. Restart recovery returns jobs that have segments to COMPLETED instead of FAILED.
- Routes take the DB session as `Depends(get_db, scope="function")`: with the default request scope the session (and SQLite's only connection) stays open until the route's BackgroundTasks finish, starving them. Keep that scope on new routes.
- The API has no login and listens on 127.0.0.1: `TrustedHostMiddleware` (`ALLOWED_HOSTS`) blocks DNS rebinding, the SPA catch-all in `main.py` only serves files inside the build, a client-supplied `tts_audio_path` must be inside the segment's own `tts/` folder, `export_path` must be an `.mp4` under the home folder or an external drive, and overlay colours are validated (they go into ffmpeg filter graphs). Never accept other server file paths from the client.
- SQLite dev DB is capped at one writer (pool_size=1, WAL); long background pipelines write status updates, so avoid adding long-lived transactions — commit (releasing the connection) before any long `await` on an outbound AI call, as the TTS paths do.
- Export must never give ffmpeg one input per line: an app opened from Finder may only have 256 files open, and full episodes have hundreds of lines. Voices are mixed into parts `DUB_BATCH` (48) at a time (`audio_extractor.build_dub_parts`) and every burned-in subtitle goes into one timed image stream (`video_overlay.build_subtitle_track`; no subtitles are burned in since 0.4.0, but `mix_dubbed_audio` keeps the layer); `test_export_scale.py` exports 300 clips + 200 subtitle lines under a 128-file limit. Media adds one input per clip, hence `MAX_EXPORT_CLIPS` (`test_media_export.py`). The voice track is padded to the video's length (`apad=whole_dur=…`), never endlessly: with ffmpeg 8 an endless `apad` + `-shortest` sometimes kept generating silence after the video ended until ffmpeg's frame queue overflowed, failing long exports with "No space left on device" (error -28) on a disk with plenty of room. The voice track is mono and is made stereo at full level on both sides (`pan=stereo|c0=c0|c1=c0`) before it meets the stereo music: left to `amix`, ffmpeg's mono-to-stereo pan law put every export's voices 3 dB under what the preview plays (`test_the_exported_voice_is_as_loud_as_in_the_preview`).
- Burned-in Khmer subtitles are drawn with Pillow, which shapes Khmer only when it can load FriBiDi at runtime; Pillow's wheels don't include it, so the backend bundles `vendor/fribidi/<target>/libfribidi.dylib` (`scripts/build-fribidi.sh`). Without it Khmer comes out unshaped with no error.
- The desktop app bundles an **LGPL-only ffmpeg** (`scripts/build-ffmpeg.sh`): no GPL filters (e.g. `boxblur`, `eq`, `hqdn3d`, `smartblur`) and no x264 — H.264 goes through `h264_videotoolbox`. Any new filter or encoder must exist in that build, or exports fail in the desktop app only (`test_export_filters.py` guards the blur box; check with `vendor/ffmpeg/<target>/ffmpeg -filters`).
- `backend/uploads/` holds all media (per-project/job subdirectories) and is served at `/uploads`; segment/voice audio paths in the DB point into it.
